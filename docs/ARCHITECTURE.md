# Архитектура Foodmanager

## Требования

- Общий список покупок в реальном времени для семьи. Сервис многопользовательский:
  им пользуются несколько семей, и один человек может состоять в нескольких.
- Приглашение в семью по короткому коду.
- Учёт запасов: сначала ручные отметки «заканчивается» / «кончилось», затем прогноз по истории покупок.
- Любые товары: продукты, бытовая химия, аптека и т.д. Можно добавлять по штрихкоду
  или вручную, названием с описанием.
- Группировка списка по магазинам и категориям.
- Уведомления через Telegram-бота. Через него же можно добавлять товары в список.
- Вход: Google, логин с паролем, Telegram. Apple отложен, так как требует Apple Developer за $99 в год.
- Клиенты: PWA (iPhone, Android, веб) и Telegram Mini App на одной кодовой базе.
- Интерфейс на русском. Хостинг: сначала бесплатно или дёшево, затем зарубежный VPS.

## Схема

```
[React PWA / Mini App] ──REST──► [Go: API + бот + фоновые задачи] ──► [PostgreSQL]
      ▲ IndexedDB (офлайн)              │
      └────────── SSE ──────────────────┤
                                        ├──► Telegram Bot API
                                        └──► Open Food Facts
```

Всё это один Go-бинарник. В проде он запускается в Docker Compose вместе с Postgres и Caddy (HTTPS).
Переезд на другой сервер: скопировать compose-файл и дамп базы.

## Ключевые решения

| Решение | Почему |
|---|---|
| OpenAPI-first (oapi-codegen + openapi-typescript) | Фронт и бэк не разъезжаются, ошибки в контракте ловятся при компиляции |
| sqlc вместо ORM | Пишем обычный SQL, получаем типизированный Go-код |
| Миграции goose встроены в бинарник, применяются при старте | Не нужен отдельный шаг деплоя |
| Сессии в httpOnly cookie, в БД хранится только SHA-256 токена | Проще и безопаснее JWT для приложения на одном домене |
| UUIDv7 (`uuidv7()` в Postgres 18), клиент сам генерирует id | Можно создавать записи офлайн, повторная отправка не создаёт дубли |
| SSE вместо WebSocket | Нужен только канал сервер → клиент, SSE проще и сам переподключается |
| Telegram вместо Web Push | Web Push в PWA на iOS ненадёжен, а Telegram есть у всех |
| TypeScript 6, а не 7 | openapi-typescript пока использует JS-API компилятора, которого нет в TS 7 |
| VPS за рубежом | Стабильный доступ к Telegram Bot API |

## Синхронизация

1. У каждой семьи есть счётчик `households.version`. Любая запись в данные семьи
   увеличивает его, и строка получает этот номер в свою колонку `version`.
2. Клиент копит изменения в очереди в IndexedDB и отправляет их на сервер.
   Мутации идемпотентны за счёт id, сгенерированных на клиенте.
3. Клиент запрашивает `GET /sync?since=N` и получает все строки с `version > N`.
   Удалённые строки приходят как tombstone (`deleted_at`).
4. SSE-событие «у семьи X теперь версия N» говорит клиенту, что пора сделать новый запрос.
5. Конфликты решаются по правилу «последняя запись побеждает» для каждой строки.

## Модель данных

| Таблица | Назначение | Этап |
|---|---|---|
| `users`, `auth_identities`, `sessions` | аккаунты и способы входа | 1 ✅ схема |
| `households`, `memberships`, `invites` | семьи, роли, инвайт-коды | 1 ✅ схема |
| `categories`, `stores` | группировка списка | 2 |
| `household_products` | товар семьи: название, описание, категория, магазин, порог | 2 |
| `list_items` | позиции списка: количество, единица, комментарий, кто добавил, куплено ли | 2 |
| `stock` | статус `ok` / `low` / `out`, при желании количество | 5 |
| `purchase_events` | история покупок, из неё строится прогноз | 5 |
| `telegram_links`, `notification_settings` | привязка бота и настройки уведомлений | 6 |
| `global_products` | штрихкод → название и бренд. Общий для всех семей, без семейных данных | 7 |

## Штрихкоды

- Сканирование камерой через пакет `barcode-detector` (zxing-wasm): форматы EAN-13/8, UPC, DataMatrix.
  Нужен он потому, что в Safari встроенного детектора нет.
- Из DataMatrix «Честного знака» берётся GTIN (AI `01`).
- Поиск идёт по порядку: каталог семьи → `global_products` → Open Food Facts.
  Если ничего не нашлось, пользователь вводит название, и оно сохраняется в `global_products`.
- Сценарии: «кончилось» (дома), «купил» (в магазине), «положил в запасы».

## Прогноз «пора купить»

Для товара нужно не меньше трёх покупок. Считается медиана интервала между ними.
Когда прошло около 90% интервала, а статус всё ещё `ok`, бот спрашивает, добавить ли товар в список.
Ответ «ещё есть» сдвигает прогноз.
