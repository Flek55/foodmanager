# Деплой на VPS

В итоге получится `https://<имя>.duckdns.org` с настоящим HTTPS-сертификатом.
Приложение ставится на телефоны и работает офлайн. Каждую ночь делается бэкап базы.

```
Интернет ──443──► Caddy (HTTPS, сертификаты) ──► app (Go + фронт) ──► Postgres
                                                                     ▲
                                                 backup (pg_dump раз в сутки)
```

Всё запускается одной командой `docker compose`. Наружу открыты только порты 80 и 443.

## 0. Что понадобится

| Что | Зачем | Цена |
|---|---|---|
| VPS с Ubuntu 22.04/24.04, 1 vCPU, 1–2 ГБ RAM, 10+ ГБ диска | сервер | обычно несколько сотен рублей в месяц |
| Поддомен на [DuckDNS](https://www.duckdns.org) | адрес и HTTPS | бесплатно |
| Приватный репозиторий на GitHub | доставка кода на сервер | бесплатно |

**Как выбрать VPS:**
- **Локация в Европе** (Нидерланды, Германия, Финляндия): хорошая задержка из РФ и стабильный доступ к Telegram Bot API.
- **Оплата из России:** многие зарубежные провайдеры не принимают российские карты. Ищите тех, кто принимает оплату из РФ: карты РФ, СБП или криптовалюту.
- **Бесплатно:** у Oracle Cloud Always Free есть бесплатные VM, но для регистрации нужна зарубежная карта.
- **Память:** если RAM всего 1 ГБ, скрипт настройки сам добавит swap, без него сборка образа может не влезть.

## 1. Домен на DuckDNS

1. Зайдите на duckdns.org (через Google или GitHub).
2. Придумайте поддомен, например `ivanovy`. Получится `ivanovy.duckdns.org`.
3. В поле **current ip** впишите IP вашего VPS и нажмите **update ip**.
4. Проверьте на своём компьютере: `nslookup ivanovy.duckdns.org` должен вернуть IP сервера.

Сертификат выпустится, только когда домен уже указывает на сервер.

## 2. Код на GitHub

На своём компьютере:

```sh
# создайте ПРИВАТНЫЙ пустой репозиторий на github.com, затем:
git remote add origin git@github.com:<you>/foodmanager.git
git push -u origin main
```

## 3. Первичная настройка сервера

```sh
ssh root@<IP-сервера>

# ключ, которым сервер будет читать репозиторий (только чтение)
ssh-keygen -t ed25519 -N "" -f ~/.ssh/github_deploy
cat ~/.ssh/github_deploy.pub
```

Добавьте этот публичный ключ в GitHub: репозиторий → **Settings → Deploy keys → Add deploy key**.
Галочку «Allow write access» **не** ставьте.

```sh
cat >> ~/.ssh/config <<'EOF'
Host github.com
  IdentityFile ~/.ssh/github_deploy
EOF

git clone git@github.com:<you>/foodmanager.git /opt/foodmanager
cd /opt/foodmanager
bash deploy/setup-server.sh
```

`setup-server.sh` ставит Docker, включает файрвол (наружу открыты только SSH, 80 и 443),
автоматические обновления безопасности и fail2ban. Если памяти меньше 2 ГБ, добавляет swap.

## 4. Настройка и первый запуск

```sh
cd /opt/foodmanager
cp deploy/.env.example deploy/.env
openssl rand -base64 32 | tr -d '/+='   # это будет пароль базы
nano deploy/.env                          # DOMAIN, ACME_EMAIL, POSTGRES_PASSWORD
bash deploy/update.sh
```

Первая сборка занимает несколько минут. В конце скрипт покажет статус контейнеров
и ответ `/api/health` с версией (коротким хешем коммита).

Откройте `https://<домен>` и зарегистрируйтесь. Создайте семью и отправьте близким ссылку-приглашение.
На телефоне: **Профиль → Установить на телефон** (Android), а на iPhone через Safari: «Поделиться» → «На экран Домой».

## 5. Обновления

Закоммитили и запушили на своём компьютере, затем на сервере:

```sh
cd /opt/foodmanager && bash deploy/update.sh
```

Миграции базы применяются автоматически при старте. Приложение перезапускается за 1–2 секунды:
открытые клиенты переподключаются сами, а изменения, сделанные за это время, ждут в офлайн-очереди.

## 6. Бэкапы

Каждые сутки `pg_dump` пишет файл `deploy/backups/foodmanager-ДАТА.sql.gz`.
Хранятся последние 14 дней (`BACKUP_KEEP_DAYS` в `.env`).

**Бэкап на том же сервере не спасёт, если пропадёт сервер.** Время от времени копируйте бэкапы к себе:

```sh
# на своём компьютере
scp "root@<IP>:/opt/foodmanager/deploy/backups/*.sql.gz" ./foodmanager-backups/
```

Восстановление (полностью заменяет текущую базу). Этот порядок проверен на локальной копии прод-связки:

```sh
cd /opt/foodmanager
dc="docker compose -f deploy/docker-compose.yml"
$dc stop app
$dc exec backup sh -c 'dropdb foodmanager && createdb foodmanager &&
  gunzip -c /backups/foodmanager-ДАТА.sql.gz | psql -q -v ON_ERROR_STOP=1 -d foodmanager'
$dc start app
```

## 7. Логи и мониторинг

```sh
dc="docker compose -f deploy/docker-compose.yml"
$dc ps                 # статус и healthcheck
$dc logs -f app        # логи приложения (JSON)
$dc logs caddy         # выпуск сертификатов, ошибки прокси
```

Логи ограничены по размеру (5 файлов по 10 МБ на сервис), диск они не забьют.

Бесплатный внешний мониторинг: заведите на UptimeRobot (или аналоге) проверку
`https://<домен>/api/health` раз в 5 минут. Если сервер упадёт, придёт письмо.

## 8. Безопасность сервера

- Войдите по SSH-ключу и отключите вход по паролю: в `/etc/ssh/sshd_config`
  поставьте `PasswordAuthentication no`, затем `systemctl restart ssh`.
  Сначала убедитесь, что вход по ключу работает, иначе можно потерять доступ.
- `deploy/.env` содержит пароль базы. Он в `.gitignore`, не коммитьте его.
- Postgres и само приложение наружу не открыты. Снаружи доступен только Caddy.

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| Браузер ругается на сертификат или сайт не открывается | `$dc logs caddy`. Чаще всего домен ещё не указывает на IP сервера, или у провайдера VPS закрыт порт 80/443 (у некоторых есть свой файрвол в панели) |
| `502 Bad Gateway` | `$dc ps`, затем `$dc logs app`. Приложение не стартовало, обычно из-за ошибки в `.env` или недоступной базы |
| Сборка падает с нехваткой памяти | проверьте swap: `swapon --show` |
| Живые обновления не приходят | откройте `https://<домен>/api/households/<id>/events` после входа: должен идти поток с `: ping` каждые 25 с |
